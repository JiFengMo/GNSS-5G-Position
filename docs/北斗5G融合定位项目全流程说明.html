北斗与5G融合定位项目全流程说明

项目：ToA_5G　整理日期：2026年10月22日

本文面向项目开发、实验操作和后续交接，说明从射频采样、信号处理、时间与坐标建模，到定位解算、网页监看和验证归档的完整流程。算法说明对应当前仓库实现，参数同时区分配置文件显式值、程序缺省值和离线参考实验值。后文命令均在项目根目录的 Linux 或 WSL 终端执行；命令中的真实 IQ 路径、设备序列号和实验输出名称需按实际填写。

项目当前已经形成两条独立信号处理链：5G 以 SSB 同步、PBCH/MIB 解码和相对时延监看为主；北斗 B1C 已形成捕获、连续跟踪、电文、星历、伪距和单点定位链，并增加了 B210 实采入口。融合目录提供双系统独立钟差的离线鲁棒 WLS。PRS、5G 独立三维定位和双设备在线融合尚未形成可直接验收的完整闭环。

1 项目目标与当前完成程度

1.1 总体目标

用 USRP 接收北斗 B1C 和 5G NR 信号，从北斗提取卫星伪距，从 5G 提取基站时间观测，在统一接收历元、坐标和时间约定下估计接收机位置。北斗提供卫星轨道与广域定位约束，地面 5G 锚点作为另一类距离约束。两路接收机或两种系统可能具有不同的时间偏差，因此融合模型保留两个独立接收钟差。

完整目标流程为：射频与时钟准备 → UHD 硬件采样 → IQ 连续性检查 → 北斗/5G 各自同步跟踪 → 观测有效性检查 → 同历元对齐与坐标转换 → 独立钟差 WLS → 定位质量检查 → 记录和界面展示。当前程序实际运行时，北斗与 5G 分别启动，主配置中的融合开关尚不承担统一调度。

3 数据流与处理时序

3.1 5G 路径

主配置选择接收子配置 → 配置解析与设备初始化 → 获取带硬件时间戳的 IQ → 环形缓存与同步任务队列 → 搜索 PSS → SSS 识别 PCI → PBCH DMRS 假设与 MIB 解码 → 进入跟踪 → 提取 SSB 网格 → LS 信道估计 → 插值平滑 → CIR → 整数峰与分数峰 → 相对时延 CSV 和监看 JSONL。

只有真实 PBCH/MIB 解码且保持锁定时，SSB provider 才继续测量。同步任务与记录线程有各自容量和丢弃统计；网页冻结不影响采样和计算。

3.2 北斗离线路径

真实 IQ 文件 → 读取 20 ms 捕获窗口 → PRN/多普勒/码相位搜索 → acquisition.csv → 按各星种子连续跟踪 → 逐星 prn_XX.csv → 18 秒电文帧同步和校验 → frames.csv 与 ephemerides.csv → 公共采样历元构造伪距 → 卫星位置、钟差及 SPP → solutions.csv、observations.csv、exclusions.csv → 导入 SQLite → 网页回看。

离线各阶段通过文件衔接，既可单独重跑，也可由 run_BDS_only.sh --offline 顺序调度。电文与定位阶段读取已有跟踪结果，不重复读取 IQ 做相关。

3.3 北斗在线路径

B210 → 独立 UHD C API RX 线程 → 硬件时间戳和连续样本编号 → 有界 IQ 队列 → DSP 线程 → 原有捕获/跟踪/电文/定位核心 → 实采 JSONL → Python 增量 reader → 网页。

在线只使用在目标时刻之前已经收齐的完整有效电文。发生 overflow、队列丢弃或采样缺口时，连续段、帧时间锚点和本地接收钟状态必须重建；不能用断流前的完整帧立即恢复定位。

3.4 融合路径

当前入口是人工准备的一组统一观测 CSV → bds5g-positioning → 位置和双钟差 JSON。GNSS 定位输出并未自动转成融合 CSV；5G 在线测量也没有自动接入这个离线入口。时间分组、坐标转换和两套设备观测的对应关系须在进入求解器之前完成。

4 环境与构建流程

4.1 运行环境

在线设备链路以 Linux 为主，WSL 用于 Linux 编译、配置核查和离线回归。Windows/MinGW 只作为离线验证环境，不能由 Windows 构建成功推断 USB 射频链可用。项目使用 C11；北斗在线部分还需要 C++17。使用预设需要 CMake 3.21 以上和 Ninja；普通 CMake 入口最低为 3.16。Python 服务要求 Python 3.9 以上。

GNSS 构建需要 FFTW3；UHD 仅在对应在线目标启用时需要。典型 Ubuntu 依赖为 build-essential cmake ninja-build pkg-config libfftw3-dev libuhd-dev python3。先核对现有开发环境，再补齐缺失包。

修改既有 .f 值或 anchors.csv 后通常无需重新编译，但要停止并重新启动受影响程序。修改 C/C++、头文件、CMake 或增加新的解析字段需要重编译。修改 Python 要重启服务；修改网页 HTML/CSS/JS 通常刷新即可。磁盘当前配置和程序启动时加载的配置可能不同，实验追溯以已加载快照为准。

5.3 参数调整顺序

先固定真实设备与数据格式，再固定采样率、中频和中心频点；然后确定信号搜索范围、目标身份和时钟来源；最后调整增益、环路和记录频率。每次实验尽量只改变一个类别，保存原配置、副本、日志和结果，便于区分射频变化、同步变化和显示变化。

7 5G 同步与测时算法

7.1 IQ 接收与任务调度

接收线程从 UHD 获取 IQ 和硬件采样时间戳，写入环形缓存，并维护绝对样本位置和间断计数。同步 actor 消费独立任务队列，结构默认深度 NR_SYNC_Q_DEPTH=8。队列丢弃、接收间断、环形缓存溢出和监看丢弃是不同的故障来源，不能合并成一个“丢包数”。

采样块需要保留实际采样率、块首硬件时间、处理窗口位置、当前频率和目标 PCI。多频点搜索中的观测在不同时刻取得，不能仅因存入同一列表就视为同一定位历元。

7.2 PSS 粗同步与频偏

PSS 搜索对三个 NID2 本地参考做相关，获得候选时刻和相关指标。处理保留最多四个候选，再执行精同步与 PBCH 尝试。设定目标 PCI 时还会限制 NID2，并缩小 PBCH 尝试数量。

SSB provider 的附加门限包括 PSS 指标至少 0.15、频偏绝对值小于 14,900 Hz，以及粗同步位置距输入边界至少约 16 样本。这些是当前源码常量，不是配置文件中的独立可调字段，也不能用于解释北斗捕获统计量。

PSS 或循环前缀相关估计载波频偏后，在提取 OFDM 符号时补偿。频偏补偿的目的在于恢复子载波正交性，并提高 SSS、DMRS 和 PBCH 解码的可靠性；一个很高的相关峰本身仍不足以确认小区锁定。

7.3 SSS 与 PCI

SSS 搜索 NID1，并与 NID2 组合得到 PCI=3×NID1+NID2。精同步保留候选 PCI 与时序偏移，再供 PBCH 评估。指定 target_pci 会强制使用目标身份作为后续假设，因此“配置中写了 PCI84”不能替代真实 PBCH/MIB 校验成功。

7.4 PBCH DMRS 和 MIB

对 PCI、SSB 索引、半帧等假设生成 DMRS 参考，估计信道、噪声和公共相位，构造 PBCH 软信息并进行后续 BCH/CRC 解码。这里 PBCH 日志中的 BCH 指广播信道处理，不等同于北斗 BCH(21,6) 和 BCH(51,8) 的码字检查。

解码成功后记录 SSB 索引、SFN、MIB payload 及其公共 SCS、SSB 子载波偏移、CORESET0 和 SearchSpace0 信息。工程还能计算 Type0 CSS、SIB1 接收计划等诊断，但不能据此认定已经完成完整商用网络接入、SIB1 全解码或可用的基站坐标获取。

失败阶段会分别标为 window、demod、dmrs_weak、dmrs_ambig、bch_crc 等。应先依据失败阶段定位问题，再调整参数；不要仅靠提高增益反复尝试。

7.5 跟踪

锁定后根据已知 SSB 周期和样本时刻预测后续位置，更新 CFO 和时序。当前 CFO 跟踪中包含 0.82×旧值+0.18×CP估计 的平滑，以及基于 DMRS 公共相位的残余频偏修正，后者增益为 0.20。定时跟踪比较偏移候选 {0,-1,+1,-2,+2}，按指标选择整数移动并维护累计移位。

这些系数属于当前源码实现。失锁后回到搜索，不应延续已经失效的 MIB 或把旧曲线当成最新完整处理链。

7.6 SSB 提取与 LS 信道估计

SSB 使用 4 个符号、每符号 240 个相对子载波的网格表示。参考资源包括 PSS、SSS 和 144 个 PBCH DMRS。已知导频 X 与接收资源 Y 的 LS 原理是用 Y 除以 X；实现利用本地参考的共轭约定完成复数乘法，并加入小量防止除零。接收参考与发射参考的共轭方向必须一致。

测时支路先在已知资源上得到信道，再在每个符号内补齐子载波，最后沿符号方向做 0.25、0.5、0.25 的平滑并在边界归一化。PBCH 软解调前端另使用 OAI 的 16 点插值滤波系数；这与测时支路的一般插值不是同一个处理函数。

7.7 CIR 和亚栅格峰值

当前 nr_ssb_build_cir() 把四个符号的信道平均，对 240 个频域点计算 240 点逆变换，输出 cir_len=240、os_factor=1。它没有在这里执行可配置的高倍率零填充。峰值指标是最大幅值除以平均幅值，随后质量映射为 min(peak_metric/8,1)，低于或等于 1 时给零质量；这些量不是已标定距离标准差。

整数峰取 CIR 幅值的全局最大点。设左、中、右幅值为 yL、yC、yR，三点抛物线插值的实现表达式为：

frac = 0.5 * (yL - yR) / (yL - 2*yC + yR)

分数修正限制在 -0.5至+0.5；边界峰、点数不足或分母过小时取 0。全局最强峰不保证是最早直达径，多径下可能出现偏差。分数插值提高峰位置表达的细度，不会自动补回信号有效带宽或消除多径。

7.8 当前测量拼接和绝对 TOA 边界

当前函数按下式构造接收位置：

rx_arrival = block_timestamp + coarse_offset
             + cumulative_tracking_shift + peak_index + frac
relative_delay_ns = (rx_arrival - block_timestamp) * 1e9 / Fs
toa_ns = (rx_arrival - tx_timestamp) * 1e9 / Fs
range_m = toa_ns * 1e-9 * 299792458

前两项是代码的当前定义。相对时延以当前处理窗口为参考，不是传播时延。绝对 TOA 还要求 TX 时间与 RX 时间属于同一已验证时间体系，并配对同一次发射事件，扣除硬件链路延迟。

源码核查有两个需要独立验收的接口问题。第一，当前 240 点 CIR 的索引被测量构造函数直接加入原始采样计数；对占用带宽的逆变换，延迟栅格原则上与变换点数和子载波间隔有关，因此需要核对 CIR 栅格到 ADC 样本域的转换与符号起点偏置，不能直接把当前显示数值当作已标定纳秒。第二，nr_toa_get_last_tx_timestamp() 读取的是 nr_anchor_write.c 的进程内静态变量；单独启动锚点与接收机不会共享这个变量，当前接收入口没有从 tx_event.csv 自动导入配对时间。因此分别启动两个程序并不形成绝对测距闭环。

上述判断来自当前函数调用和存储方式，是接口核查结论，不是本次新增的射频测量结果。本次文档整理未修改算法。工程应先补齐发射事件传递、同源配对、时间尺度和延迟标定，再验收绝对距离。

7.9 时延统计的解释

相对时延 CSV 保留接收块时间、到达位置、分数峰、相对样本数/纳秒、滑动均值、jitter、PCI、SSB、CFO、SNR、峰指标、质量和 MIB。jitter 是当前滑动窗内按 N 分母计算的标准差。不同 PCI、频点、窗口起点或重锁段不应无条件混在一起分析；滑动稳定不等于绝对误差很小。

30.72 Msps 下一个原始采样间隔约 32.552 ns，对应光程约 9.759 m；4.092 Msps 下约 244.379 ns，对应约 73.263 m。这只是原始采样尺度示例，最终估计精度受有效信号带宽、信噪比、同步、模型和标定影响，不能用原始采样间隔直接给出最终精度结论。

8 5G 锚点与 PRS 的真实实现范围

8.1 锚点配置和发射流程

默认 anchor0 请求 3.6 GHz、30.72 Msps、外部参考和 PPS、40 dB TX 增益。程序等待时钟状态，设置下个 PPS 时间原点，计算周期样本数，在当前硬件时间之后提前排定 burst，写 UHD 并生成 log/tx_event.csv。默认周期来自 20 ms 缺省值。当前调度使用查询硬件当前时间再加 lead 的方式，不是已经证明长期严格锁定公共 epoch 栅格的多锚点调度。

anchors.csv 目前包含两个示例：anchor0/PCI42/SSB0 位于 (0,0,3) m，anchor1/PCI43/SSB0 位于 (20,0,3) m，absolute_time_valid 为 1、硬件延迟为 0。它们是示例几何和声明，不能据此认为硬件时延已经标定为零。坐标看起来是局部实验坐标，不能直接当作融合 ECEF 输入。

8.2 波形与身份映射限制

当前 nr_ssb_build_tx_plan() 把 anchor_id、PCI 和 SSB index 初始化为 0；网格构造函数返回 valid=0；OFDM 生成入口调用固定参数 nr_v0_ssb_build_burst_iq(0,1,...)。因此锚点 CSV 的 PCI42/43 与波形/计划没有形成已核验的自动映射。发射日志能够生成，不等于两个锚点已发出正确身份的标准可定位 SSB。

需要逐项核对发射身份、PBCH/MIB、周期、绝对时刻和接收侧识别结果，才能把该入口从测试信标推进到受控定位锚点。当前代码保留了通道和计划接口，适合后续补齐，但不应越过这些步骤解释结果。

8.3 PRS 与 5G 位置模块

PRS provider 当前 acquire/track 会直接把 locked 设为 1，extract_meas 以零峰偏移调用通用测量构造；三个 PRS 算法文件分别为 stub。test_prs_toa 仅引用 provider 并返回成功，不能证明 PRS 波形处理正确。

5G 的 nr_pos_build_equations() 只清空输入，nr_pos_solve_wls() 清空输出并设置 valid=0；其测试只验证入口可调用。nr_meas_assoc_anchor() 也未实际匹配 PCI/SSB，当前直接返回 0。历元管理器只是收集缓存再弹出，尚不是严格按公共时刻进行多锚点插值配对。与此相对，src/fusion/solver/fusion_wls.c 才是另一个实际实现的离线 WLS，不要混淆同名概念。

9 北斗 B1C 信号和输入约定

9.1 信号模型

当前实现支持 PRN1至63 的数据主码、导频主码和导频子码。主码长 10230 码片，码率 1.023 Mcps，周期 10 ms；导频子码长 1800，每主码周期一个子码符号，总周期 18 s。二进制 0 映射为 +1、1 映射为 -1。

本地副本采用窄带 BOC(1,1) 数据/导频联合处理，沿用 CU-SDR 路径；不是完整宽带 QMBOC 接收。射频中心为 1575.42 MHz，数据路和导频路按其相位关系处理。码生成、采样副本与相关器符号约定必须保持一致。

9.2 在线与离线参数不能混用

RF 中心 1575.42 MHz 文件参数不直接给 RF 调谐

ci8 每个复数样本 2 字节；cf32 每个复数样本 8 字节，离线按小端 float32 读取。skip-samples、absolute_sample 和码相位样本数均指复数样本，不是字节。若把 ci8 当 cf32 读取，即使程序没有立即退出，得到的幅相和时间也没有正确物理意义。

采样副本沿用 MATLAB 右端点 ceil 索引约定，包含其浮点取整行为，便于逐样本对照。在 18 Msps 下每个 10 ms 主码周期名义上有 180000 个复数样本，20 ms 捕获窗口有 360000 个。4.092 Msps 下对应 40920 和 81840 个。连续跟踪的每历元实际样本数由残余码相位和瞬时码率决定，不应强制每行都等长。

10 北斗捕获算法

10.1 搜索空间

捕获同时搜索 PRN、多普勒和码相位。离线参考默认为 PRN1至63、多普勒 -5000至+5000 Hz、粗步长 50 Hz、细步长 25 Hz、10 ms 相干积分、统计量门限 10。当前在线配置改为 -8000至+8000 Hz、粗步长 250 Hz、细步长 25 Hz，积分和门限不变。这是两套不同搜索参数。

在线粗搜索共 65 个频点，离线 50 Hz 粗搜索为 201 个频点。扩大频率范围或缩小粗步长都会增加计算量；提高粗步长也可能改变低信噪比条件下的捕获结果，应以独立验收而不是仅以速度决定参数。

10.2 相关与归一化

读取连续 20 ms，默认以 10 ms 有效积分和补零 FFT 进行相关，覆盖整个码相位。粗步长恰好对齐 FFT 频率栅格时复用信号 FFT；不对齐时逐频点混频再 FFT。多个 PRN 复用工作空间，不保存完整二维搜索矩阵。

数据与导频的联合幅值统计量采用下面的代码等价表达式：

joint = (sqrt(11)*abs(Rdata) + sqrt(29)*abs(Rpilot)) / sqrt(40)
metric = joint / sqrt(var(IQ[0:Ncoh]) * Ncoh)
acquired = metric > threshold

方差用 N-1 分母。该统计量既不是 CIR 峰均比，也不是 C/N0。0 Hz 频率可以是合法结果，不能以频率是否非零代替 acquired 判决。

10.3 精细频率与码周期模糊

获得粗峰后将相关滞后折叠到一个 10 ms 主码周期，从原始连续 IQ 截取精搜区间，在粗频点附近正负一个粗步长内搜索细频率；可能略超出粗搜索边界。carrier_hz=IF+doppler_hz。捕获的 code_phase_samples 是输入窗口内、周期折叠后的零起始码相位，没有绝对发射时刻，不能直接乘光速形成距离。

离线 CLI 支持 1至10 ms 积分，但连续跟踪和电文链使用完整 10 ms。参数要求上下界差是粗步长整数倍、细步长整除粗步长。采样率边界为 2.046至100 Msps，在线对硬件回读微小误差另有容许范围。

10.4 输出和退出状态

捕获 CSV 包括 PRN、acquired、carrier_hz、doppler_hz、coarse_doppler_hz、code_phase_samples、input_start_sample、peak_metric、fine_metric。捕获阶段 cn0_db_hz 为 NaN，不输出伪造载噪比。返回 0 表示有捕获；7 表示正常完成但无捕获；2 为参数错误；3 为文件/内存错误；6 为算法参数或输入无效。

11 北斗连续跟踪算法

11.1 初始化与相关器

捕获结果给每星提供起始样本、载波频率和码相位。初始码率利用载波多普勒辅助：在 1.023 Mcps 基准上加入 doppler/1575.42MHz×1.023Mcps。每通道维护码 NCO、载波 NCO、残余相位和完整 64 位样本计数。

每个主码周期分别积累数据与导频的 Early、Prompt、Late 复相关，E/P 和 P/L 各偏移 0.06 个主码码片。数据/导频使用参考的 11:29 联合鉴别器权重。Prompt 输出既用于质量检查，也用于后续电文符号判断。

11.2 DLL 和 PLL

二阶 DLL 默认带宽 1 Hz、阻尼 0.7，按码误差更新码 NCO。三阶 PLL 默认 18 Hz，使用对符号翻转不敏感的 Costas 鉴别器；导频按相对数据路的正交关系处理，避免数据位或导频子码翻转被误判为 180 度载波误差。环路跨周期保留残余相位，不把每个块都当作新信号。

参数 缺省值 作用
dll_bandwidth_hz 1 Hz 码环响应和噪声权衡
dll_damping 0.7 二阶码环阻尼
pll_bandwidth_hz 18 Hz 载波环带宽，当前校验不允许超过18
early_late_offset_chips 0.06 单边 E/L 间隔
quality_epochs 50 约每0.5秒更新质量

min_lock_indicator 0.6 锁定指示器门限

bad_windows_to_lose 2 两个坏窗后失锁

这些是核心 defaults；在线 .f 只显式暴露其中部分，不能把所有核心结构成员都当成已支持的配置项。缩小 DLL/PLL 带宽可能减小噪声，但减慢收敛并降低动态跟踪能力；调整时要比较失锁次数、误差与电文成功率。

11.3 质量与假锁抑制

Prompt 功率一阶/二阶矩用于估计信号和噪声，构成窄带相关 C/N0；不把非物理解取绝对值后冒充有效值。质量窗口尚未收齐时为 NaN，理想零噪声可为正无穷。该量未经射频总功率标定。

数据路以 I 轴、导频路以 Q 轴形成对符号翻转不敏感的锁定指标，并按信号功率组合。每个历元又拆成前后两半，利用相位差估计残余频率，防止 10 ms Costas 环落到约 50 Hz 的假锁分支。有效性同时依赖 C/N0、锁定指示器、码误差和半历元频差，不是看单一 C/N0 曲线。

11.4 状态与重捕获

初始状态 pull_in，连续好窗后转 locked；连续坏窗后转 lost。lost 在当前 generation 内为终止状态，只有显式重捕获/重置才能重新进入 pull_in。C/N0 回升本身不会直接恢复有效标志。

离线自动重捕获在完整码周期边界执行，默认每通道最多尝试3次、至少间隔约1秒，在当前频率附近正负1000 Hz 搜索。成功后 generation 递增、NCO 重置，重新等待锁定；reacquire_ok 不代表立刻有有效电文。在线 live engine 另有调度：失锁通道约隔1秒重试，初始未捕获通道在已有工作通道后约每30秒重搜，间隔按采样流时间计算。

11.5 连续性和输出解释

同一 generation 中应满足“本行 absolute_sample+sample_count=下一行 absolute_sample”。sample_time_s=absolute_sample/Fs 是记录内时间；epoch 是代次内序号，record_index 是输出行号。不能简单用行号乘10 ms代替精确时间，也不能跨重捕获拼接载波相位。

输出每星 prn_XX.csv、全局 events.csv、summary.csv 和 run.json。应分别看运行完整性、有效历元、失锁计数、重捕获和 EOF 部分样本。返回0表示请求的完整历元数已处理，不保证所有通道锁定。核心拒绝 NaN/Inf 和未显式重置的样本缺口；不足一个完整主码周期不输出伪历元。

12 北斗导航电文与星历

12.1 从相关输出到帧

每10 ms主码周期产生一个符号。导频以 pilot_q_p 符号与1800长度子码匹配，相关绝对值必须为1800，等价于 MATLAB 的至少1799.5门限。一帧18秒，当前要求1800个符号全部正确，因此弱信号下一个错误即可导致漏帧。

数据路以 data_i_p>0 判1。先检查 BCH(21,6)，必要时反转整帧极性，再检查 BCH(51,8)，得到PRN和SOH。门限20/50实际上要求当前路径的完整无错码字，不进行BCH纠错。

12.2 解交织和校验

后1728个符号按36×48矩阵解交织，零基行2、5直到32组成子帧3，其余组成子帧2。当前跳过LDPC，直取子帧2前600位和子帧3前264位，分别做CRC24Q；两者都通过才输出878位信息/CRC内容和星历。

CRC检查用于拒绝错误信息，不等于纠错。当前不使用LDPC校验部分恢复有错比特，所以完整帧率、弱信号敏感性和首定位等待时间受此限制。后续若增加软判决或LDPC，必须保留现有参考路径作回归。

12.3 连续性和时间

1800个输入必须 locked、valid，属于同一generation，样本和epoch连续。采样缺口、失锁或重捕获会清空未完成窗口，不从两段信号拼成一帧。帧尾不足1800个符号不输出。

WN是BDT周号；HOW是周内小时数；SOH在输出中已乘18成为小时内秒，TOW=HOW×3600+SOH。帧首的absolute_sample是接收文件位置，TOW是电文发射时间标签，两者不共享原点，不能直接相减测距。

12.4 字段解析与适用性

输出轨道、钟差、群延迟、HS健康、DIF/SIF/AIF完整性和SISMAI等字段。SatType=1/2/3分别表示GEO/IGSO/MEO。deltaA是相对参考半长轴差，不是sqrt_a。轨道距离用m、角度用rad、钟差与群延迟用s。Page1电离层参数属于BDGIM，不应当作GPS Klobuchar系数。

每帧重新初始化字段，缺少的扩展页为NaN，不把旧页面残留当成新帧数据。当前解析Page1部分电离层/UTC和Page3 BGTO；其他页并未完整解析所有历书。当前C实现将IODC按10位读取，对早期MATLAB多读一位的问题作了单独修正；对照报告需保留该有意差异。

输出 frames.csv、ephemerides.csv、summary.csv 和 run.json。complete表示输入读完，decoded_frames才表示有效帧数。帧valid仍不等于可用于定位，后续还需健康、时效、连续段及模型支持检查。

13 北斗伪距与单点定位

13.1 统一接收采样历元

所有卫星必须在同一个absolute_sample上构造观测。找到包含该采样点的完整跟踪历元，用残余码相位和瞬时码率插值，然后结合当前连续段的有效帧时间锚点：

code_phase = rem_code_phase + code_rate/Fs * (sample - epoch_first_sample)
transmit_time = frame_TOW + ((epoch - frame_epoch) + code_phase/10230)*0.01
raw_pseudorange = c * (local_receive_time - transmit_time)

周号与周内秒分开维护，处理周边界。帧锚点必须属于同一generation/连续段，且后续帧的时间增量和主码周期数一致。失锁后的新段即使有很好的C/N0，也要先获得本段完整帧才能构造有效发射时间。

13.2 本地接收时间与钟差

首个本地接收时刻按最大有效发射时刻加68.802 ms初始化。该偏置是参考算法本地钟初值，不是天线传播真值。每历元解算接收位置X/Y/Z和米制钟差b，再执行 local_time -= b/c，之后按公共样本步长推进。

因此首历元clock_correction_m可以很大，后续主要是两次更新之间的剩余修正，不能把该列直接当作未重置的累计硬件钟偏。更改初始偏置应主要被钟差吸收，而不应改变正确收敛的位置。

13.3 轨道和卫星钟差

卫星状态沿用B1C专用参考。MEO参考半长轴27,906,100 m，IGSO为42,162,200 m，加deltaA、ADot、平均角速度与变化率，解开普勒方程并加入谐波、节点与倾角变化，得到发射时刻ECEF。

卫星钟差由钟多项式、相对论项和负T_GDB1Cp组成。当前沿用联合数据/导频跟踪模型，不另外减ISC_B1Cd；如切换成纯数据测距，必须重新核对时延模型。当前不支持GEO，遇到该类型明确拒绝，不能用MEO公式代替。

轨道和钟差的应用层最大年龄均默认7200秒，结合完整WN/TOW判断，防止把一周前的数据因取模误当作新数据。

13.4 观测改正和解算

原始伪距包含接收钟差。先按 raw+c×satellite_clock_s 做卫星钟差改正，再在解算中估计接收钟差。进一步扣接收钟差得到接收机修正后的伪距，其中仍有大气、多径和码测量误差。

SPP使用等权四状态最小二乘，从地心初始化，采用参考的10次迭代路径，加入传播期间地球旋转改正。线性方程用Householder QR，拒绝秩不足或病态几何；坐标必须有限、收敛且在地球附近。至少需要4颗独立有效卫星，且几何可解，数量条件本身不足以保证定位。

默认每200 ms输出一次，5度仰角门限在获得初始位置后应用，并在后续历元重新评估所有候选星。HS、DIF、SIF、AIF任何一个非零都排除。HDOP/VDOP在本地ENU中计算，不能把ECEF的XY/Z直接当作水平与垂直分量。

13.5 大气模型和当前缺项

默认对流层沿用固定参数：海平面、1013 mb、293 K、50%相对湿度，不使用真实站高或实测气象。可用 --no-tropo 关闭。当前没有电离层改正、URA/SISMAI加权、RAIM、多径专用处理或载波相位定位。即使成功输出valid=1，也只是通过当前模型和工程检查，不代表完整性认证。

13.6 输出与失败行为

solutions.csv 保存采样时刻、接收BDT估计、ECEF、WGS84经纬高、钟差、DOP、RMS、用星数和状态；observations.csv 保存逐星发射时间、三类伪距、卫星坐标/钟差、仰角、对流层项和残差；exclusions.csv 保存排除原因；run.json 保存参数与完整性。

不足卫星、几何退化或不收敛时输出无效状态和NaN坐标，不把上次坐标当作新结果。少于4个有效帧通道时可以正常完成并输出空表。输入损坏、CRC错误或电文与实际跟踪不匹配属于输入错误，不应解释为“信号暂时不够”。

14.2 设备时间与实际采样率

启动配置外部参考和PPS，检查ref_locked与PPS跳变，在未知日期的PPS上归零硬件时间，约0.2秒之后定时开始RX。未知PPS只提供秒边界，不提供UTC/BDT日期，也不能单凭两台都选择external就声称绝对时间对齐。

硬件回读Fs可能带小数。当前捕获容许每10ms与整数样本数相差不超过0.01 sample，等价于距最近100Hz网格不超过1Hz；只对FFT和码缓冲长度取整，混频、码副本、跟踪和时间计算仍使用实际Fs。不能把回读值强改成请求值来消除误差。定位周期映射到最近硬件采样间隔，实际时间以样本数除实际Fs为准。

14.3 队列和吞吐

fc32每样本8字节，4.092 Msps、16秒队列约523.8MB，即约499.5MiB。配置上限约2GiB。队列吸收短时积压，不会提升DSP的长期吞吐。初次全PRN捕获可能显著耗时，要观察处理延迟与队列增长。

满队列会丢弃旧积压并计数，触发断段和重新捕获。UHD overflow或正向样本跳变也不能被拼接；时间倒退报错。原始IQ默认不落盘，在线JSONL只含处理结果和状态，因此不能事后从它重新计算完整IQ算法。

14.4 首定位的因果约束

必须完成初始捕获、环路确认、获得帧边界并收齐18秒帧，才可能有本段在线位置。等待下一帧边界、弱信号漏帧、处理积压会进一步延长墙钟时间。离线回溯可在收到完整帧后解算帧首附近的更早采样点；在线不能使用这种未来信息。

16 离线融合 WLS

16.1 统一观测格式

timestamp_ns,source,source_id,source_x_m,source_y_m,source_z_m,pseudorange_m,sigma_m,cn0_db_hz,valid

source=0为B1C，1为NR SSB，2为NR PRS。source坐标是观测时刻所需的ECEF米，伪距和sigma均为米。timestamp_ns需由上游统一，不能混入不同日期/时基。当前CSV加载器不会按timestamp自动分组，应用一次读取整个文件求一个解，故输入应是事先组织好的一组同历元观测。

16.2 模型和状态

单系统状态为位置加一个钟差，共4维；同时包含北斗和NR时为 [X,Y,Z,b_BDS,b_NR] 共5维。模型为几何距离加对应系统米制钟差。至少需要4条或5条有效观测，还要有足够独立几何；同一锚点的重复测量不能当成新的独立几何源。

残差为观测减预测，几何方向导数组成设计矩阵H。每轮构造加权法方程，使用带主元选择的消元求增量。这里使用法方程，与北斗SPP的Householder QR不是同一数值路径。

16.3 鲁棒权与收敛

初始权为1/sigma²，标准化残差绝对值为z。z超过Huber门限k时再乘k/z，降低离群观测权重。默认k=3、最大15轮、位置增量范数小于0.001m时收敛。该收敛阈值约束迭代步长，不代表毫米级实际精度。

当前不输出完整协方差或完整性认证。返回0代表收敛，1代表迭代未收敛，负值代表输入/数量/方程异常。输出位置、两个钟差、残差RMS、使用观测数和converged。不能仅看JSON文件存在判断解有效。

16.4 NR适配器

适配器要求测量valid、锚点absolute_time_valid且PCI匹配，先做 corrected_toa_ns=toa_ns-calibrated_delay_ns，拒绝非有限或非正值，再乘光速形成伪距。sigma使用 max(0.5,12/max(peak_metric,1)) 米的启发式映射，未经过真实射频误差统计标定。

适配器当前将NR输出source固定为SSB，并把snr_db写入公共cn0_db_hz字段。这是现有兼容映射，SNR不等于GNSS C/N0；分析公共质量列时必须保留来源语义。融合配置中2m/1.5m标准差并未被该入口自动读取。

16.5 尚未自动完成的工作

在线接入还需要：卫星观测到公共结构的可靠导出；5G绝对/伪距时间模型；多设备共同历元；局部锚点到ECEF；系统间时间转换；标定数据和身份匹配；按时刻分组；观测有效性和几何检查；在线位置输出与UI连接。两台B210共用10MHz/PPS有助于建立频率与秒边界关系，但不会代替这些处理。

17 网页与记录流程

17.1 5G监看

C端限频创建快照并放入固定队列，由独立记录线程写JSONL；Python服务仅监听127.0.0.1，通过GET提供bootstrap、state、recordings、replay。网页按频点/PCI/SSB选目标，展示Summary、SSB Trace和Results。不同事件的阶段不会拼成虚构的一次完整处理。

默认状态记录200ms、阶段快照1000ms、网页轮询200ms，过期门限5000ms。单段128MiB、本次最多8段，约1GiB轮换容量；旧实验不自动删除。文件每段重复config，保存当时加载参数，回看不从当前磁盘配置反推旧实验。

source_mode=controlled或commercial只声明场景；time_model=shared或receiver_bias只声明时间模型；absolute_toa_calibrated默认0。它们不会配置设备时钟或完成标定。UI只有在底层测量、事件时钟状态、时间模型和标定等满足时才显示可用的绝对量。

17.2 北斗离线导入

ui/import_gnss.py 将同次实验捕获/跟踪/电文/定位文件导入新目录中的data.sqlite和run.json，保留参数快照、源文件元数据和SHA256。只有跟踪也可导入；若提供定位，必须同时提供匹配电文。应在源文件停止写入后导入，SQLite索引不自动追踪后续CSV追加。

离线展示四种数量：捕获、当前有效跟踪、当前完整电文就绪、定位用星。它们不应强制一致。回溯位置可以早于所依赖电文的收齐时间，界面需标识离线回溯及available_s；这不是实时提前获得位置。

17.3 北斗在线读取

实采记录在 log/gnss-live/<实验>/events-<段号>.jsonl，独立于5G目录。每段32MiB、每次最多8段，约256MiB轮换。类型包括config、hardware_origin、runtime、acquisition、tracking、frame、position、event、gap。

北斗live以程序运行且状态不超过3秒为connected，current还要求处理滞后不超过2秒且reader无未读积压。超过门限时当前锁定和位置留空，历史仅用于诊断。reader有每次4MiB、单行256KiB等上限，保留滚动历史；当前不支持完整实采归档直接导入SQLite。

17.4 网页功能边界

冻结只暂停显示；关闭网页不会停止算法。当前HTTP没有修改配置、启停设备、上传执行或IQ重算功能。5G接口position_solver仍为false；北斗实际位置使用独立GNSS接口，不能因该5G标志为false而误认为北斗没有定位。

19.2 电文和定位

自动重捕获记录7星共21帧通过双CRC；禁用重捕获为6星18帧。帧首采样点、极性、878位信息/CRC与参考一致，IODC修正单列。真实帧类型为MEO，其他类型与扩展页覆盖范围见各验收记录。

两种定位模式均为278/278有效历元。自动模式首历元7星，之后6星；PRN25解算后仰角约0.893度，按5度门限排除。中位坐标约纬度40.009973328度、经度-105.244333287度、椭球高1616.116m；这是参考记录位置，不是本实验室设备位置。

自动模式后277个历元相对中位数的ENU样本标准差约0.465/0.506/0.849m，残差RMS约0.016至2.165m。没有天线真值，这些只能表示短期散布和内部一致性。C/MATLAB坐标分量约1e-8m差异代表数值实现一致，绝不是纳米级实际定位精度。
