# 北斗 B210 实采接收链路

`sh run_BDS_only.sh` 默认构建并启动 `build/gnss-radio/src/GNSS/bds-b1c-live` 和北斗只读 UI，默认端口 8766。使用另一台 B210、外部 10 MHz/PPS，参数入口是主配置 `gnss_config` 指向的 `config/GNSS/bds_b1c.f`。5G 保持原有独立入口。

## 输入、算法与时间

独立 UHD C API 后端只创建接收流，主机格式 `fc32`、线上格式 `sc16`，不用 5G 收发设备初始化。空 `serial` 选择 UHD 发现列表中的第一台设备；非空时作为 UHD 发现过滤条件，匹配不到直接报错，选择后检查型号为 B210。实际采样率、频率、增益和带宽从硬件回读。

B210 的分数时钟合成可能使 UHD 回读采样率带有小数，例如请求 4092000 Hz 而回读 4092000.0037 Hz（此数值是测试案例，不是目标机实测）。启动日志用高精度打印请求值、实际值及每 10 ms 样本数；监看配置同时保存请求和实际值。捕获允许每码周期与整数样本数相差不超过 0.01 sample，即距最近的 100 Hz 采样率网格不超过 1 Hz。只取整 FFT/码缓冲长度，捕获混频、本地码采样、连续跟踪、电文和定位时间模型全部保留实际速率；不通过把实际速率覆盖成配置值来通过检查。超出此边界仍报错并打印具体数值。定位输出周期取最近的硬件采样间隔，实际时间始终由样本数除以实际采样率计算。

启动先设置外部参考/PPS，检查可用的 `ref_locked` 和 PPS 跳变，然后在未知 PPS 上将硬件时间归零，未来 0.2 秒定时开始连续采样。未知 PPS 不提供真实日期，也不声明两台 USRP 的绝对 UTC 时间已对齐。RX 数据沿硬件时间戳转成 64 位采样计数，相对本次首块记零；硬件起点与计数通过字符串记录，避免浏览器整数精度损失。

采样线程只收包、维护计数并移动 IQ 到有界队列；DSP 线程复用 `b1c_acquisition.c`、`b1c_tracking.c`、`b1c_navigation.c`、`b1c_position.c`，没有另写一套解调/定位数值算法。完整 20 ms 搜索窗口用于捕获，已经跟踪的通道不重复输入搜索窗口。失锁通道约隔 1 秒重试；初始未捕获的通道在已有通道工作后约每 30 秒重新搜索。这些间隔按采样流时间计算，实际墙钟耗时取决于算力。

导航帧必须在目标采样点前完整收齐，且与当前观测来自同一有效连续段，才能用于在线解算。最少四星、健康/完整性、星历年龄等检查沿用原有定位条件；首次位置获得后再应用仰角门限。原 MATLAB 导出的离线回溯定位工具继续保留，仅在显式 `--offline` 路径使用。

采样时间倒退会报错。正向间断、UHD overflow 或队列丢弃会清除连续帧锚点和接收机时钟状态，断段并重新捕获；原始 IQ 不默认落盘。队列默认 16 秒，在 4.092 Msps 下约 500 MiB，最大配置 2 GiB。它用于吸收短时积压，不保证 CPU 能持续处理全部通道；超限时丢弃旧积压并计数，不能把丢弃的数据当作连续采样。

## 构建与输出

Linux 需安装 CMake 3.21+、Ninja、pkg-config、C/C++17 编译器、FFTW3 和 UHD 开发包。Ubuntu 可准备 `build-essential ninja-build pkg-config libfftw3-dev libuhd-dev`，设备固件/镜像沿用已有 B210 环境。

```bash
cmake --preset gnss-radio
cmake --build --preset gnss-radio --parallel 2
ctest --preset gnss-radio
sh run_BDS_only.sh --check
sh run_BDS_only.sh
```

构建输出 `build/gnss-radio/src/GNSS/bds-b1c-live`，运行输出：

- `log/launcher/bds-<时间>-<PID>/`：configure、build、receiver、UI 日志。
- `log/gnss-live/<同名实验>/events-<段号>.jsonl`：已加载配置、硬件起点、运行状态、捕获、跟踪、电文、定位和间断事件。每段 32 MiB，每次最多保留 8 段；旧实验目录不自动删除。

界面展示边界、离线入口和回看方法见 [北斗 UI](../../../ui/gnss.md)。日志轮换和历史缓存有界，但实采记录尚不能直接导入离线 SQLite 回看；不声称保留完整实验历史或支持原始 IQ 重算。

## 当前验证与目标机验收

2026-10-22 在 WSL Ubuntu、GCC 13、UHD 4.6.0.0 环境编译并链接真实后端。新增检查覆盖有界队列、采样间断、零 IQ 不产生坐标、原有 MATLAB 参考帧进入在线解码与因果解算；测试专用接收替身覆盖大于 2^53 的硬件计数、overflow、倒退时间、设备不存在与退出清理。替身只链接到 `test_b1c_live_transport`，生产 `bds-b1c-live` 链接真实 UHD，不含模拟输入回退。

Python 接口测试覆盖序列号配置、子进程清理、过期/滞后隐藏坐标、断流、帧分页、半行写入与轮换；浏览器使用明确标记的测试显示记录验证冻结、模式切换、分页和窄屏布局。这些都不代表真实 B210 已捕获卫星或实时性能已达标。

目标 Linux/B210 上按以下顺序验收：

1. `uhd_find_devices` 确认设备；需要固定北斗设备时把其 serial 写入配置，否则留空按默认发现选择。核对天线实际接口、10 MHz、PPS 与北斗天线/前端。
2. `sh run_BDS_only.sh --check` 检查配置，然后 `sh run_BDS_only.sh`。查看终端及 `receiver.log`，确认实际采样率/射频参数、参考锁定和 PPS。
3. 网页依次观察捕获、稳定跟踪、完整有效帧、有效定位；无足够信号时保持空白，不以网页启动成功作为射频通过。核对处理延迟、CPU、内存和队列/UHD 丢弃计数。
4. 用不存在的 serial 验证明确失败且不连接另一台；恢复配置后检验 Ctrl+C 与设备异常退出的进程清理。
5. 在受控实验中检查断流后旧位置不再作为当前结果、重捕获后等待新连续帧；用已知天线位置进一步检查绝对定位误差。

本机没有连接目标 B210，因此上述射频、外部时钟实物状态与持续运行算力验收仍待实机完成。
