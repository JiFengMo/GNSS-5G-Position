# SSB TOA 时间单位与定时插值修正（2026-10-24）

## 修正内容

1. 保留现有 240 点 CIR，在 `nr_cir_t.bin_width_s` 记录 `1/(240×SCS)` 秒。通过 `nr_toa_cir_delay_samples` 将峰索引、小数 CIR 格点换算为实际接收采样单位后，再构造硬件到达时间。
2. 插值后将循环索引展开到 `[-N/2,N/2)`，正确处理负残余时延；第 0 点和最后一点使用循环左右邻点插值。
3. 定时跟踪候选按 `[-2,-1,0,1,2]` 排序，只用有效的相邻等间距点插值，限制小数偏移至 ±0.5；全部无效时不移动窗口。相同相关度优先保留更接近当前窗口的候选。
4. 到达时间保留整数硬件计数与 `[0,1)` 小数部分，负残余向整数部分借位，检查溢出和非有限输入。硬件计数不整体转换为 double。
5. `sync.frac_offset_samp` 作为跟踪窗口诊断量；最终到达时刻为“硬件块起点 + 粗定时 + 累计整数窗口移动 + CIR 残余”，不再额外叠加跟踪小数诊断量，避免重复计数。
6. 监看记录增加 `cir_bin_width_ns`，界面区分 CIR 小数格点和接收采样点，循环峰值边界也展示实际使用的三个点。旧 JSON 字段名保留兼容，单位见 `ui/protocol.md`。

`nr_toa_build_meas` 的输入改为已换算的 `double residual_delay_samp`。PRS 的调用只做接口适配，不代表实现了 PRS 算法。代码、头文件一起重新编译，不支持混用旧静态库。

## 独立物理模型测试

`test_ssb_toa.c` 构造单径频响：

`H[k] = exp(-j×2π×k×SCS×残余时延)`

模型不使用工程的发射信号生成器，直接经过实际 CIR 构建、寻峰、循环插值、单位转换和接收时间构建。共覆盖 264 个组合：

- SCS：15、30 kHz。
- 接收采样率：7.68、15.36、30.72、61.44 Msps。
- 正负整数 CIR 延迟、零延迟、正负小数延迟和半格点延迟。
- FFT 窗口相对移动 −1、0、+1 个接收采样点，确认还原的到达时刻保持在同一误差界内。

整数 CIR 格点要求接近浮点舍入精度。三点幅度抛物线对 sinc 峰只是近似，小数格点用例的允许误差为四分之一 CIR 格点；这是回归容差，不是实机测距精度声明。30 kHz 下四分之一格点约 34.72 ns，15 kHz 下约 69.44 ns。该修正没有提高信号有效带宽，也没有实现超分辨率或首径识别。

额外覆盖：循环首尾三点插值、奇偶长度的有符号展开、NaN/Inf、空/零 CIR、非法峰索引、缺失时间刻度、无效采样率、超过 2^53 的计数、负小数借位、整数溢出与无发射事件时绝对测量无效。

另以合成 SSB 走完整 provider 的“解调 → LS → 插值 → CIR → 接收时刻”链，检查 ±3 个采样点的窗口变化与零 IQ 拒绝。绝对 TOA 分支只通过测试专用设备写回调注入进程内发射时间，不连接 SDR，也不代表跨进程发射事件已接通。

`test_ssb_timing.c` 使用实际 PBCH 前端在明确的物理偏移上计算相关度，再独立算出正确左右邻点的三点插值，与实际跟踪输出比较；覆盖五种初始窗口偏移、非零整数修正、内部峰与缺失候选。

## 复现与运行

项目根目录、已准备依赖的 Linux 环境：

```bash
cmake --preset all-offline
cmake --build --preset all-offline --parallel 2
ctest --preset all-offline
```

输出在 `build/all-offline/src/5G/`，新增 `test_ssb_timing`，现有 `test_ssb_toa` 已替换空 CIR 检查为物理时延与边界测试。CTest 结果在该构建目录的 `Testing/Temporary/LastTest.log`。

只运行本次相关测试：

```bash
ctest --test-dir build/all-offline -R 'nr_ssb|nr_monitor' --output-on-failure
```

目标 Linux 的 UHD C++ 开发依赖齐全后，使用现有入口：

```bash
sh run_5G_only.sh
```

该入口增量编译接收机并启动监看，新测量记录按修正后的时间单位生成；旧日志回看不会被重算，不能与新日志混为同一算法版本。网页刷新以加载格点单位说明。
