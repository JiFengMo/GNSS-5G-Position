# 独立原始 IQ 采集

在 Linux 工程根目录运行：

```bash
# 只检查配置与磁盘空间；不加载 UHD、不打开设备
sh run_5G_only.sh --capture-iq --check

# 按独立配置打开 B210，采满指定时长后退出
sh run_5G_only.sh --capture-iq

# 使用另一份同格式采集配置；路径包含空格时加引号
sh run_5G_only.sh --capture-iq --config 'config/5G/iq_capture.f'
```

默认独立配置为 `config/5G/iq_capture.f`，不读取或切换 `config/config.f`，不改变普通 `sh run_5G_only.sh` 和 `--ui-only` 的流程。原始采集模式不启动 UI、不编译 C/C++ 接收机、不运行 PSS/SSS/PBCH 或定位，不根据解码成功与否选择 IQ，也不扫频、自动扫增益或发射信号。

## 配置与依赖

需要 Linux、Python 3.9+、可加载的 UHD 动态库和已可用的 B210 固件/USB 环境。通过 Python 标准库 ctypes 调用 UHD 公共 C 接口，按 UHD 4.6 头文件核对；不依赖 UHD Python 模块、NumPy、pip 安装或 Boost 开发头文件。普通 5G C++ 接收机仍有自身的编译依赖，不受这一独立模式影响。

默认参数参考工程已有 n1 / PCI84 配置：

| 项目 | 默认值 |
|---|---|
| 设备 | B210，`serial=2512531` |
| 中心频率 | 2114.55 MHz |
| 复数采样率 | 30.72 MS/s，以 UHD 回读实际值为准 |
| 主时钟 | 30.72 MHz；0 可让 UHD 选择 |
| 接收带宽 | 30 MHz |
| 接收增益 / 天线 | 64 dB / RX2 |
| 时钟 / 时间源 | internal / internal |
| 时长 | 3 秒，约 368.64 MB 原始文件 |
| SSB 场景提示 | 15 kHz、20 ms、目标 PCI84、n1 |

开始实测前，核对配置里的设备序列号、实际天线端口、频点、采样率和增益。默认参数不是现场信号存在或设备吞吐达标的证明。`serial` 留空时要求只发现一台匹配设备；多台匹配会报错，不随机选择。`clock_source=external` 必须检测到参考锁定，`time_source=external` 必须检测到 PPS 跳变。

SSB SCS、周期、频率偏移、目标 PCI 和频段只保存为回放提示，不是解码得到的测量结果。所有参数的单位、范围、枚举和路径规则都写在配置文件对应注释中；未知、重复、缺失项会报错。

## 输出与格式

每次在 `log/iq-capture/<时间>-<唯一后缀>/` 创建新目录，不覆盖之前的实验，也不自动清理历史数据：

| 文件 | 内容 |
|---|---|
| `capture.c16` | 接收 IQ，little-endian 有符号 int16，交错 `I0,Q0,I1,Q1,...`；每复数样本 4 字节，单通道 |
| `capture.json` | 配置请求值、UHD 回读实际参数、设备地址/版本、启动锁定快照、首块硬件时间、样本统计和最终完整性状态 |
| `capture.meta.txt` | 便于检查的伴随参数：实际采样率、频率、样本数、首样本计数和 SSB 场景提示 |
| `blocks.csv` | 每个成功写入块的文件字节偏移、样本数、硬件样本计数及完整秒/小数秒时间戳 |
| `config.f` | 本次加载的配置快照 |
| `capture.log` | 采集启动、进度、完成/失败原因；UHD 库直接打印的原文仍显示在终端 |

数据的 host/wire 格式均为 `sc16`。没有软件频偏补偿、数字滤波、重采样、归一化、通道估计或插值；文件是 UHD 接收接口输出的基带 IQ，不是 ADC 内部未经硬件射频/数字前端处理的直接采样。

写盘使用独立线程及有界队列。默认队列上限约 32 MiB，另有当前接收块、转换副本和文件缓冲的内存开销；不声称目标机一定能持续写入 122.88 MB/s。启动前按请求值检查空间，设备打开后按实际值再次检查，并额外预留 64 MiB 用于索引与状态文件。

实际采样率保留完整浮点精度，不用取整采样率覆盖硬件回读。目标样本数取 `round(实际采样率×时长)`，最终时长以写入样本数除以实际速率为准。硬件时间按整秒与小数秒保存，大整数计数在 JSON 中使用字符串；设备时钟不复位，也不声明与 UTC 或另一台设备的历元已经对齐。参考/LO/PPS 状态是启动检查快照，不是全程锁定证明。

## 完整性与中断

每个接收块都检查 UHD 错误码、序列错误、有效时间戳、样本长度和下一块起点的连续性。overflow、超时、时间倒退/跳变、磁盘写入异常或队列满时立即停止接收，不静默丢弃后继续拼接成“连续”文件。支持短读和最后一个不足整块的数据。

Ctrl+C / SIGTERM 请求停止 RX，再排空已入队的数据并关闭文件。中断退出码为 130；其他失败为非零。若磁盘或系统强制终止导致无法写最终状态，之前的 manifest 保持 `complete=false`，不把残留文件当作完成记录。

使用数据前检查 `capture.json`：

- `status=complete`、`complete=true`：目标样本数已写入且文件已正常 flush/fsync。
- `status=interrupted` 或 `failed`：本次采集未完成，查看 `error`。
- `continuous_prefix=true`：已正常保存的部分构成连续前缀，文件长度与索引统计匹配；这不代表达到了请求时长，也不代表测距或信号解码通过。
- `actual=null` 或 `samples_written=0`：初始化失败或尚无可用 IQ，不应拿空文件回放。

## 验证与下一步

2026-10-24 在 WSL / UHD 4.6 环境运行了 14 项专项测试：显式注入的测试接收替身覆盖原始字节不变、实际小数采样率、超过 2^53 的硬件计数、短读、时间间断、overflow、中断清理、队列满、写盘失败、目录不覆盖、配置与磁盘检查、带空格路径和 shell 选项分发；另以受控写盘停顿验证真实有界队列满时明确报错且只保存先前入队的数据。另外直接加载了真实 libuhd，核对全部所用 C 符号、版本读取和 metadata 句柄创建/释放，未打开任何 SDR。

```bash
python3 -m unittest discover -s ui/tests -p test_iq_capture.py -v
```

这些测试不代表真实 USB/射频/磁盘吞吐验收。下一步在目标 Linux/B210 上先采一份 3 秒记录，检查完整性和实际参数，再将整个实验目录提供给离线分析；需要保留 IQ 本体，不要只复制 `.meta.txt` 或日志。现有 `replay_toa_iq` 主要检查同步/PBCH，尚未完整加载这些场景提示并输出修正后的 TOA；不能直接把其默认参数下的结果当作本模式的完整验收。
